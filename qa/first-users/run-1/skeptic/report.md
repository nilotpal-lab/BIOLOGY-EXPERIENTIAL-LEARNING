## Friction points

1. **No confirmation on "Remove imported dataset"** — "One accidental click and my imported dataset is gone — where's the 'are you sure?'" — http://localhost:4173/#/library — expected a confirm dialog before a destructive action; actual: instant silent deletion (toast absent for removal). Severity **2**. [08-after-removal.png]
2. **Import auto-navigates away and hijacks the active network** — "I imported a dataset in the Library and suddenly I'm in the Explorer with my 3-node test web as the active network." — http://localhost:4173/#/explore — expected to stay in the Data Library context; actual: forced navigation + network switch (at least announced by a toast). Severity **1**. [06-import-success.png]
3. **JSON role vocabulary not shown where I type** — "My trophic roles were silently normalized to 'other' because the valid values aren't listed in the dialog (only a 'Documented JSON schema' link I nearly missed)." — http://localhost:4173/#/library (import dialog) — expected the accepted role values inline; actual: warning-only disclosure after validation. Severity **1**. [05-import-dialog.png]
4. **Ecosystem category silently defaults to Freshwater** — "My 'meadow' got filed under Freshwater because I didn't notice the default." — import dialog — expected no silent categorization; actual: default preselected. Severity **1**. [05-import-dialog.png]
5. **App-level About / Terms / Privacy pages: not found** — "There's no page saying who builds this beyond a 'Biology for Engineers · Team 1' chip, no terms, no privacy policy." — nav has only the six feature sections + Methodology. Mitigated by repeated "stored in this browser only, never uploaded" statements and zero account/payment flows, so for THIS tool it matters little. Severity **1**.
6. **"Verified" is self-attested within the UI** — "The app says the research webs were 're-derived from the committed source files', but the UI can't show me that audit trail — I have to take it on faith or re-derive it myself from the DOI." — mitigated: DOIs/source URLs, CC0 licences and full node/link CSV exports are provided so an outsider CAN re-check. Severity **2**.

## Trust verdict

This is the most disclosure-heavy course tool I have used. What it discloses well: every screen separates "Illustrative demo" from "Research source verified" and the two validation fixtures are labelled as such; each research network carries a full provenance record (authors, Dryad DOI, article DOI, CC0 licence, source URL, node-unit caveats — e.g. Palmyra prey are families, not species); the methodology page publishes the exact cascade rules, metric formulas with guards, ranking tie-breaks and a re-runnable in-browser test suite (70/70 passed twice); limitations ("structural disruption, not extinction", no population dynamics, recorded-links-only, connectance can rise) are repeated on the landing page, in the methodology and around the outputs. The claims are backed by visible provenance: I could open every citation, and my own import test confirmed the tool refuses to auto-verify — my invented dataset was honestly stamped "Research source provided, validation pending — never verified automatically", and my nonstandard roles were normalized with visible warnings. Data control also passes: import is local-only, and my imported dataset could be removed (too easily — no confirm). What it fails to disclose: app authorship beyond a team chip, any terms/privacy page (low impact given the local-only model), and the "verified" badge remains the team's self-attestation — the UI gives me DOIs and CSV exports to re-derive it, but I cannot see the verification audit itself from inside the app. Verdict: I would cite this tool in coursework for structural food-web exercises, citing the underlying Dryad sources it lists and repeating its own "not extinction, not population dynamics" caveats; I would not present its demo networks or outputs as field evidence — and the app itself tells me not to.
